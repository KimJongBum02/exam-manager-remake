# ExamManager 재설계 — 기능 설계서

- 상태: 초안, 2026-11-13
- 근거: 사용자가 작성한 재설계 요구 원문(기능 설명 텍스트)
- 범위: 교수용 앱, 학생용 앱, 두 앱 사이의 TCP 통신
- 관련 문서: [기능 설계서(현행 제품 기준)](../functional-design.md), [UI/UX 설계서](../ui-ux-design.md)
- 이 문서는 "처음부터 다시 만드는" 제품의 기능 범위를 정의한다. 화면 배치·문구는 UI/UX 설계서에서 다룬다.

## 1. 전제와 제약

| 항목 | 내용 |
|---|---|
| 운영 환경 | 학교 강의실 PC, Windows, 1920×1080 배율 100% |
| 규모 | 학생 30~40명, 교수 1명 |
| 서버 | 별도 서버 없음. 교수 앱이 서버, 학생 앱이 클라이언트인 TCP/IP 2계층 |
| 학사 DB | 제공받을 수 없음. 명단은 교수가 첨부하는 엑셀이 유일한 기준 |
| 언어 | C#(화면·흐름) + C++(OS 연동). DllImport 경계에서 데이터가 깨지지 않아야 함 |
| OS 라이브러리 | 같은 기능을 Windows가 제공하면 직접 구현하지 않고 그것을 쓴다 |
| 테스트 | 1인 개발. 교수 PC 1대 + 학생 PC 1대의 1:1 검증만 가능 → 다중 학생 동시성은 설계로 보장해야 함 |

## 2. 시스템 구성

### 2.1 역할

- **교수 앱 = 서버**: 서버 소켓 생성, 자신의 IP·포트 노출, 연결 수락, 전체 시험 흐름의 주체.
- **학생 앱 = 클라이언트**: 서버 주소로 접속, 로그인, 지시 수신·수행·보고.
- 학생끼리는 통신하지 않는다. 모든 상태는 교수 앱이 보유한다.

### 2.2 언어 분담

| 계층 | 언어 | 담당 |
|---|---|---|
| 화면·시험 흐름·상태 | C# (WPF) | 대시보드, 마법사, 채팅, 퀴즈, 엑셀 로그 |
| 소켓·패킷·파일 전송 | C++ DLL | 서버/클라이언트 소켓, 패킷 조립, 파일 조각 송수신 |
| 프로세스·네트워크 통제 | C++ DLL | 프로세스 감시/종료, 방화벽 규칙, 화면 캡처 |
| 압축·암호화 | C# + 외부 exe | 7za.exe 호출 |

현행 모듈 구성(NetworkLib_Native / ProcessControl / FileControl + NetworkInterop)은 검증된 분할이므로 재설계에서도 기준으로 삼는다.

### 2.3 DllImport 경계 규칙 (데이터 깨짐 방지)

1. 문자열은 UTF-8 바이트 배열로만 주고받고, C++ 소스는 BOM + `/utf-8` 옵션을 강제한다. (한글 리터럴이 조용히 깨진 전례가 있음)
2. 구조체는 고정 크기 필드 + 명시적 패킹만 사용한다. 가변 길이 데이터는 포인터 + 길이로 전달한다.
3. 패킷은 `[타입(고정)][길이(고정)][본문]` 형태로 고정하고, 수신 길이에 상한(예: 4MB)을 둔다. 상한이 없으면 헤더 하나로 서버를 멈출 수 있다.
4. 콜백(C++ → C#)은 델리게이트 수명을 C# 쪽에서 붙잡아 둔다.

## 3. 교수용 기능

| ID | 기능 | 내용 |
|---|---|---|
| P-01 | 서버 시작 | 서버 소켓 생성, 자신의 IP·포트 표시. 포트는 다른 프로세스와 충돌이 적은 값을 고정 사용 |
| P-02 | 연결 수락 | 클라이언트 연결 요청 대기·수락. 수락/거절 사유를 학생에게 회신 |
| P-03 | 접속 현황 | 학생별 접속 상태, **최초 접속 시각**과 **재접속 여부·시각**을 보유·표시 |
| P-04 | 명단 선탑재 | 학번·이름 엑셀을 첨부해 대시보드를 미리 채운다. 명단에 없는 학번·이름은 로그인 거절 |
| P-05 | 1:1 채팅 | 교수 ↔ 학생 개인 채팅. 학생끼리는 불가 |
| P-06 | 전체 화면 모니터링 | 접속 학생 전체의 화면을 320×180 썸네일로 표시 |
| P-07 | 화면 상세보기 | 썸네일 클릭 시 해당 학생만 1920×1080 고화질 캡처 시작, 창을 닫으면 썸네일로 복귀 |
| P-08 | 원격 제어 | 상세보기 화면에서 해당 학생 PC 조작. Windows 원격 데스크톱(Desktop Sharing) API 사용 |
| P-09 | 퀴즈 | OX 퀴즈, N지선다 퀴즈. 문제와 정답을 입력해 학생에게 전송하고 응답을 집계 |
| P-10 | 시험 운영 | 준비 → 배포 → 시작 → 종료·수집 → 로그 출력 (5장) |
| P-11 | 로그 출력 | 당일 시험 로그를 엑셀로 출력(ClosedXML). 열: 학번 / 이름 / 출석 여부 / 부정행위 건수 / 부정행위 목록 |

보조 규칙
- 학생 목록 정렬은 학번 순으로 고정한다(좌석·접속 순 아님).
- 되돌리기 어려운 동작(원격 제어 시작, 전체 적용, 종료)은 대상과 영향을 확인한 뒤 실행한다.

## 4. 학생용 기능

| ID | 기능 | 내용 |
|---|---|---|
| S-01 | 서버 주소 설정 | 서버 주소를 지정해 클라이언트 소켓 생성. 자동 탐색 방식은 재검토 대상(9장) |
| S-02 | 수동 IP 입력 | 서버를 찾지 못하면 IP를 직접 입력할 수 있게 한다 |
| S-03 | 로그인 | 학번·이름 입력 후 연결 요청. 교수 승인 회신이 없으면 통과시키지 않는다(실패는 닫힌 쪽으로) |
| S-04 | 명단 대조 실패 | 엑셀 명단에 없으면 사유를 알리고 재로그인시킨다 |
| S-05 | 시험 파일 수신 | 패킷 조각을 `%Temp%`에 한 조각씩 저장, 전체 수신에 성공하면 `바탕화면\시험파일`을 만들어 보관 |
| S-06 | 시험 타이머 | 시작 신호를 받으면 기본 50분 카운트다운 표시 |
| S-07 | 통제 적용 | 금지/허용 프로그램 통제와 네트워크 차단을 시작 시점에 적용 |
| S-08 | 조기 제출 | 시작 20분 경과 후(잔여 30분) 학생이 직접 제출 가능. 제출 처리 경로는 정규 종료와 동일 |
| S-09 | 흔적 삭제 | 제출 성공 후 `바탕화면\시험파일` 삭제 |
| S-10 | 원상 복구 | 시험이 정상 종료되면 프로그램 통제와 네트워크 차단을 원래대로 되돌린다 |

## 5. 시험 운영 흐름

### 5.1 시험 준비 (교수)

- 입력: 배포할 시험 문제 파일(또는 폴더), 금지 프로그램 목록, 허용 프로그램 목록.
- 처리:
  1. 7za.exe로 압축 + 암호 설정. (Windows 기본 압축은 암호화를 못 하므로 7za 사용)
  2. 암호는 `ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnpqrstuvwxyz23456789`에서 난수로 생성한다. (혼동되는 I, l, O, 0, 1 제외)
  3. 금지/허용 목록은 교수 PC와 학생 PC에 **설치된 프로그램 목록을 수집해 선택**하는 방식으로 만든다. 모든 프로그램의 원본명을 담은 카탈로그는 탑재하지 않는다.
- 결과: 배포용 암호화 압축 파일 1개 + 시험 정책 1벌.

### 5.2 시험 파일 배포 (교수 → 학생)

- 대상: 연결이 살아 있는 학생 PC 전체.
- 처리: 파일을 패킷 조각으로 나눠 전송 → 학생은 `%Temp%`에 조각 저장 → 완료 시 `바탕화면\시험파일`로 합본.
- 교수 화면: 학생별 수신 **완료 / 진행 / 미완료**를 표시하고, 미수신 학생만 골라 재전송할 수 있어야 한다.
- 이 단계에서는 암호를 보내지 않는다.

### 5.3 시험 시작 (교수 → 학생)

- 처리: 시작 신호 + **압축 암호**를 함께 전달 → 학생 앱이 압축을 해제한다.
- 암호를 시작 시점에야 주는 이유: 배포 직후 임의 해제를 막기 위함이다(부정행위 방지).
- 동시에 적용: 금지/허용 프로그램 통제, 네트워크 차단(방화벽 차단 규칙 방식), 50분 타이머.
- 부정행위 감지 건은 교수 화면에 즉시 알리고 로그에 누적한다.

### 5.4 시험 종료·답안 수집 (학생 → 교수)

- 트리거: 교수의 종료 또는 학생의 조기 제출(5.6).
- 학생: `바탕화면\시험파일` 안의 작업 결과를 다시 압축한다. **재암호화는 하지 않는다**(교수가 열 수 없게 되므로).
- 전송 후 교수 PC 저장 경로: `바탕화면\답안파일\{시험일자}\{학번_이름}.7z`
  - 날짜 폴더로 한 번 더 묶어 회차가 쌓여도 섞이지 않게 한다.
- 교수 화면: 학생별 수집 성공 / 진행 / 실패 / 미응답을 구분하고 실패 건은 재시도할 수 있어야 한다.
- 제출 성공이 확인된 학생만 흔적 삭제(S-09)와 통제 복구(S-10)를 수행한다.

### 5.5 로그 출력 (교수)

- 당일 시험 로그를 엑셀로 내보낸다(ClosedXML).
- 열: 학번 / 이름 / 출석 여부 / 부정행위 건 수 / 부정행위 목록.

### 5.6 조기 제출 (학생)

- 가능 시점: 시험 시작 후 20분 경과(타이머 잔여 30분)부터.
- 이후 처리는 5.4와 완전히 동일한 경로를 사용한다(별도 로직을 만들지 않는다).

## 6. 데이터·경로 규약

| 구분 | 값 |
|---|---|
| 암호 문자 집합 | `ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnpqrstuvwxyz23456789` |
| 압축 도구 | 7za.exe (앱과 함께 배포) |
| 학생 수신 임시 | `%Temp%` (조각 단위) |
| 학생 시험 폴더 | `바탕화면\시험파일` (제출 성공 시 삭제) |
| 교수 답안 폴더 | `바탕화면\답안파일\{시험일자}\` |
| 명단 입력 | 학번·이름 엑셀 |
| 로그 출력 | 엑셀 (ClosedXML) |

## 7. 부정행위 통제 정책

1. 금지 목록에 있는 프로그램은 실행 시 종료하고 사건을 기록한다.
2. 허용 목록이 금지 판정보다 우선한다(오탐으로 수업 도구가 죽는 것을 막는다).
3. 네트워크는 방화벽 차단 규칙으로 막고, 해제는 **답안 제출이 끝난 뒤**에 한다.
4. 통제 적용/해제 실패는 조용히 넘기지 않고 교수와 학생 양쪽 화면에 알린다. 해제 실패는 다음 수업 전체를 망가뜨리므로 가장 위험한 실패다.
5. 감지 기록만으로 부정행위를 확정하지 않는다. 판단은 교수가 한다.

## 8. 비기능 요구

- 학생 40명 동시 접속에서 상태 갱신과 썸네일 수집이 밀리지 않아야 한다(1:1 테스트로는 검증 불가 → 수신 큐·타임아웃을 설계 단계에서 못 박는다).
- 연결이 끊긴 학생은 마지막 갱신 시각과 함께 구분 표시하고, 재접속 시 기존 학생 정보에 다시 붙인다(새 학생으로 늘어나지 않게).
- 모든 실패(전송·압축·제출·통제)는 화면으로 전달한다. 로그만 남기는 실패는 결함으로 본다.
- 1920×1080 100% 기준으로 어떤 화면도 잘리지 않아야 한다.
- 앱이 죽어도 학생 PC가 통제된 상태로 남지 않도록 복구 경로를 둔다.

## 9. 미결정 사항과 위험

| # | 항목 | 내용 |
|---|---|---|
| 1 | 서버 주소 탐색 | 자동 탐색은 기존 방식에서 문제가 있었다. 고정 IP 안내 / 브로드캐스트 탐색 / 수동 입력 중 무엇을 기본으로 둘지 결정 필요 |
| 2 | 포트 번호 | 현행 9000은 다른 소프트웨어와 겹치기 쉬운 번호다. 동적 포트 범위(49152~65535)의 고정값 하나로 바꾸는 것을 권장 |
| 3 | 암호 전달 보안 | 시작 신호에 평문으로 실리면 패킷을 들여다보는 학생이 미리 얻을 수 있다. 통신 암호화 여부 결정 필요 |
| 4 | 원격 제어 | Windows Desktop Sharing API는 학생 PC의 Windows 버전·정책에 따라 동작이 달라진다. 강의실 PC 실기 확인 전에는 미확정으로 둔다 |
| 5 | 썸네일 갱신 주기 | 화면 캡처 주기(기존 2초)를 그대로 쓸지 재확인 필요. 40명 × 320×180의 대역폭이 여기서 정해진다 |
| 6 | 프로그램 목록 수집 | 학생 PC마다 설치 목록이 다르다. 교수 PC 목록만으로 고른 정책이 학생 PC에서 빗나가는 문제의 해결 방식 미정 |
| 7 | 1:1 테스트 한계 | 동시 배포, 동시 제출, 다중 썸네일은 실환경 검증이 불가능하다. 최소한 가짜 클라이언트 다수를 띄우는 부하 확인 수단이 필요 |
| 8 | 원문에 없어 제외한 현행 기능 | 설문(정답 없는 OX), 공지 팝업, 수업/자유/시험 3상태 전환, eclass 한정 웹 허용, 학생 PC 종료. 재설계에 넣을지 결정 필요 |
